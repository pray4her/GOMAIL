# Go 邮件群发管理系统 - Next.js 前端开发计划

## 零、技术栈与约定 (Tech Stack & Conventions)

-   **框架 (Framework):** Next.js (App Router)
-   **UI 组件库 (UI Library):** shadcn/ui
-   **样式 (Styling):** Tailwind CSS
-   **API 状态管理 (API State Management):** SWR
-   **全局 UI 状态 (Global UI State):** React Context API + Hooks
-   **表单管理 (Forms):** React Hook Form + Zod
-   **数据请求客户端 (Fetching Client):** Axios (或封装的 fetch)
-   **代码约定:**
    -   所有 API 数据获取/变更操作都应抽离到独立的 hooks 中 (例如 `useAccounts`, `useCreateAccount`)。
    -   所有页面和组件都应考虑加载（Loading）、错误（Error）和空数据（Empty）状态。
    -   严格遵循 `FRONTEND_API_GUIDE.md` 的接口定义。

---

## 里程碑零: 环境准备 (Milestone 0: Environment Setup)

-   **目标**: 确保所有开发人员拥有统一的开发环境。
-   **任务**:
    1.  安装 `Node.js` (推荐 v18.17 或更高版本)。
    2.  安装 `pnpm` 作为包管理器: `npm install -g pnpm`。
    3.  创建项目根目录下的 `.env.local` 文件，并配置后端 API 地址:
        ```env
        NEXT_PUBLIC_API_BASE_URL=http://localhost:8080/api/v1
        ```

## 里程碑一: 项目基础架构与全局布局 (Milestone 1: Project Foundation & Global Layout)

此里程碑旨在搭建项目的骨架，为后续功能开发提供坚实的基础。

### 1. 目标 (Goals)
-   初始化 Next.js 项目并集成核心依赖。
-   创建统一的 API 请求层。
-   构建应用的主体仪表盘布局（Dashboard Layout）。
-   建立全局状态管理的基础。

### 2. 文件结构 (File Structure)
```
/
├── app/
│   ├── (auth)/             # 认证相关页面路由组
│   │   └── login/
│   │       └── page.tsx
│   ├── (dashboard)/        # 仪表盘相关页面路由组
│   │   ├── layout.tsx      # 仪表盘布局（包含侧边栏、顶部导航）
│   │   ├── page.tsx        # 仪表盘首页 (初始为欢迎页面)
│   │   └── ...             # 其他功能模块
│   ├── layout.tsx          # 应用根布局
│   └── globals.css
├── components/
│   └── ui/                 # shadcn/ui 组件
├── lib/
│   ├── api-client.ts       # 封装的 Axios/fetch 实例
│   └── utils.ts            # shadcn/ui 工具函数
├── providers/
│   ├── auth-provider.tsx   # 认证状态提供者
│   └── swr-provider.tsx    # SWR 全局配置提供者
└── middleware.ts           # 路由中间件
```

### 3. 核心任务 (Core Tasks)

1.  **初始化 Next.js 项目**
    -   使用 `pnpm dlx create-next-app@latest` 创建新项目。
    -   运行 `pnpm dlx shadcn-ui@latest init` 来初始化 shadcn/ui 和 Tailwind CSS。

2.  **创建 API 请求客户端 (`lib/api-client.ts`)**
    -   创建一个 Axios 实例。
    -   配置 `baseURL` 从 `process.env.NEXT_PUBLIC_API_BASE_URL` 读取。
    -   设置请求拦截器，用于在每个请求中自动附加 `Authorization: Bearer <token>` 头。
    -   设置响应拦截器，用于统一处理 `data` 和 `error` 字段，简化 SWR hook 中的逻辑。

3.  **设计全局布局 (`app/(dashboard)/layout.tsx`)**
    -   这是一个**服务器组件 (Server Component)**。
    -   创建 `Sidebar` 和 `Header` 组件。
    -   `Sidebar`: 包含到各个核心模块的导航链接（仪表盘、账号、发件人等）。
    -   `Header`: 包含用户下拉菜单（显示用户名、提供登出按钮）。
    -   布局应使用 `flex` 或 `grid` 来实现，主体内容区可滚动。

4.  **全局状态提供者 (`providers/`)**
    -   在根布局 (`app/layout.tsx`) 中，包裹 `<html>` 和 `<body>`。
    -   引入 `Toaster` 组件 (来自 shadcn/ui) 用于全局消息提示。
    -   创建 `AuthProvider` 和 `SWRProvider`，并在此处包裹 `children`，为整个应用提供上下文。

## 里程碑二: 用户认证 (Milestone 2: User Authentication)

实现完整的用户登录、登出和会话管理流程。

### 1. 目标 (Goals)
-   创建功能齐全的登录页面。
-   使用 React Context 管理用户会话。
-   使用 Next.js Middleware 保护私有路由。

### 2. 文件结构 (File Structure)
```
/app
├── (auth)/
│   └── login/
│       ├── page.tsx
│       └── components/
│           └── login-form.tsx  # "use client"
└── (dashboard)/
    └── ...
/providers/
└── auth-provider.tsx           # "use client"
/middleware.ts
```

### 3. 核心组件 (Key Components)
-   `app/(auth)/login/page.tsx`: **服务器组件**，用于布局。
-   `app/(auth)/login/components/login-form.tsx`: **客户端组件 (`"use client"`)**。
    -   使用 `React Hook Form` 和 `Zod` 管理表单状态和校验。
    -   调用 API `/login` 进行认证。
    -   **UX**:
        -   登录按钮在提交时应显示加载状态。
        -   使用 `Toast` 显示登录成功或失败的消息。
        -   成功后，调用 `AuthProvider` 中的方法保存 token 并重定向到 `/dashboard`。

### 4. 状态与数据流 (State & Data Flow)
-   **`AuthProvider` (`providers/auth-provider.tsx`)**:
    -   使用 `React Context` 创建。
    -   内部使用 `useState` 存储 `user` 对象和 `token`。
    -   Token 将被存储在 `localStorage` 或 `httpOnly` Cookie 中。
    -   提供 `login(token)`、`logout()` 方法和 `isAuthenticated` 状态，供应用内其他组件消费。

### 5. 核心任务 (Core Tasks)
1.  **创建登录页面**: 实现 `login-form.tsx` 组件。
2.  **实现认证上下文**: 实现 `auth-provider.tsx`。
3.  **实现受保护路由 (`middleware.ts`)**:
    -   检查请求中的 token (从 cookie 读取)。
    -   如果用户未认证且试图访问 `/dashboard` 下的任何页面，则重定向到 `/login`。
    -   如果用户已认证且试图访问 `/login`，则重定向到 `/dashboard`。
4.  **实现登出功能**:
    -   在 `Header` 组件中添加登出按钮。
    -   `onClick` 时调用 `AuthProvider` 的 `logout` 方法，清除 token 并重定向到 `/login`。

## 里程碑三: 核心功能模块 (Milestone 3: Core Feature Modules)

按照 API 指南，逐一实现核心资源的 CRUD 管理界面。以下以 **云账号管理** 为例，其他模块可参照此模式，同时注意 API 的可用状态。

### 3.1. 云账号管理 (Account Management) - 功能完整
-   **目标**: 实现对云账号的增、删、改、查。
-   **路由**: `/dashboard/accounts`
-   **文件结构**:
    ```
    /app/(dashboard)/accounts/
    ├── page.tsx                # 主页面 (Server Component)
    ├── components/
    │   ├── account-table.tsx     # 数据表格 ("use client")
    │   ├── columns.tsx           # 表格列定义 ("use client")
    │   └── account-form.tsx      # 创建/编辑表单 ("use client")
    └── hooks/
        └── use-accounts.ts       # SWR hooks
    ```
-   **核心组件与任务**:
    1.  **数据获取 (`hooks/use-accounts.ts`)**: 创建 `useAccounts()` 等 SWR hooks 来获取和操作 `/api/v1/accounts` 数据。
    2.  **列表页面 (`page.tsx` + `account-table.tsx`)**:
        -   `page.tsx` (服务器组件) 可直接获取初始列表数据，并作为 `fallbackData` 传递给客户端组件 `account-table.tsx`。
        -   使用 `Suspense` 和 shadcn/ui 的 `Skeleton` 作为加载状态的 `fallback`。
        -   实现 `DataTable`，定义 `columns.tsx`，包括 `id`, `name`, `domain`, `status` 和 `actions` 列。
    3.  **创建/编辑功能**:
        -   实现 `account-form.tsx`，使用 `React Hook Form` 和 `Zod`。
        -   在 `account-table.tsx` 中集成 `Dialog` 组件来承载表单。
    4.  **删除功能**:
        -   在 `actions` 列中添加删除按钮。
        -   **UX**: 点击后显示 `AlertDialog` 进行二次确认。
        -   确认后调用 API (`DELETE /accounts/{id}`)，然后触发 SWR 重新验证。

### 3.2. 用户与发件人管理 (User & Sender Management) - 功能受限
-   **注意**: 根据 `FRONTEND_API_GUIDE.md`，`Users` 和 `Senders` 的部分 GET/PUT/DELETE 接口为“待开发”。计划应反映此现状。
-   **用户管理 (`/dashboard/users`)**:
    -   **初期目标**: 只实现“创建用户”功能 (`POST /api/v1/users`)。
    -   可以创建一个简单的表单页面，但用户列表、编辑、删除功能暂时不做或做成静态展示。
-   **发件人管理 (`/dashboard/senders`)**:
    -   **目标**: 实现创建发件人实体并将其关联到云账号的完整流程。
    -   **UX 流程**:
        1.  在 `/dashboard/senders` 页面，提供一个“创建发件人实体”的表单（对应 `POST /api/v1/senders`）。
        2.  显示发件人实体列表（此部分 API 待开发，可暂时只显示刚创建的）。
        3.  为每个发件人实体提供“关联云账号”功能，弹出一个表单，让用户选择一个已有的云账号并填写 `email_address` 等信息（对应 `POST /api/v1/senders/{senderId}/accounts/{accountId}`）。

### 3.3. 其他模块 (Recipients, Groups, Templates)
-   对于 `Recipients`, `Recipient Groups`, `Templates`，其 API 较为完整，可完全参照 **3.1 云账号管理** 的模式进行全面实现。

## 里程碑四: 核心业务流程 - 邮件任务 (Milestone 4: Core Business Flow)

这是应用的核心，将各个模块串联起来。

### 1. 目标
-   实现创建邮件发送任务的完整流程。
-   提供任务列表和任务详情查看页面。

### 2. 路由与文件结构
```
/app/(dashboard)/tasks/
├── create/
│   ├── page.tsx
│   └── components/
│       └── create-task-form.tsx  # "use client"
├── [id]/                         # 动态路由，查看任务详情
│   ├── page.tsx
│   └── components/
│       └── task-records-table.tsx # "use client"
└── page.tsx                      # 任务列表页
```

### 3. 核心任务
1.  **创建任务页面 (`/tasks/create`)**:
    -   `create-task-form.tsx`: **客户端组件**。
    -   表单包含 `task_name`, `recipient_group_id`, `template_id`, `scheduled_at` 等字段。
    -   **关键交互**:
        -   `recipient_group_id`: 应使用 shadcn/ui 的 `Combobox`，通过 SWR 异步加载并搜索所有可用的收件人分群。
        -   `template_id`: 同上，异步加载并搜索所有邮件模板。
        -   `scheduled_at`: 使用 `Calendar` 和 `Popover` 组件。
    -   提交时调用 `POST /api/v1/tasks`。
    -   **UX**: 成功后显示 `Toast` 提示任务已创建，并重定向到任务列表页。

2.  **任务列表页面 (`/tasks`)**:
    -   使用 `DataTable` 显示所有任务。
    -   列应包括 `task_name`, `status`, `created_at`, `scheduled_at`。
    -   `status` 字段应使用 `Badge` 组件根据不同状态（`pending`, `sending`, `completed`）显示不同颜色。

3.  **任务详情页面 (`/tasks/[id]`)**:
    -   `page.tsx`: **服务器组件**。
        -   使用 `params.id` 获取任务 ID。
        -   并行发起两个请求：`GET /tasks/{id}` 获取任务摘要，`GET /tasks/{id}/records` 获取第一页的发送记录。
    -   **UI**:
        -   顶部显示任务摘要信息（来自 `/tasks/{id}`）。
        -   下方使用 `task-records-table.tsx` (客户端组件) 显示详细的发送记录。
        -   `task-records-table.tsx` 需要支持分页功能，当用户切换页面时，使用 SWR 进行客户端数据获取。

## 里程碑五: 数据可视化 (Milestone 5: Data Visualization)

### 1. 目标
-   实现 `/dashboard` 主页的统计概览。
-   实现独立的 `/statistics` 页面，提供多维度图表。

### 2. 技术选型
-   **图表库**: `recharts` 或 `nivo` (与 shadcn/ui 风格契合)。

### 3. 核心任务
1.  **仪表盘首页 (`/dashboard/page.tsx`)**:
    -   **服务器组件**，获取全局统计数据 `GET /api/v1/statistics` (不带参数，或默认最近30天)。
    -   使用 shadcn/ui 的 `Card` 组件展示关键指标（总发送量、总打开率等）。
    -   使用 `recharts` 渲染一个简单的发送量趋势图（时间序列）。

2.  **统计详情页 (`/dashboard/statistics/page.tsx`)**:
    -   **客户端组件 (`"use client"`)**，因为需要处理交互式过滤。
    -   提供日期范围选择器 (`Date Range Picker`)。
    -   提供下拉框用于 `group_by`（按天、周、月、发件人）以及按 `account_id` 过滤。
    -   当筛选条件变化时，使用 SWR 根据查询参数动态获取 `GET /api/v1/statistics` 数据。
    -   **UX**: 图表和数据在加载时应显示 `Skeleton`。

## 里程碑六: 优化与打磨 (Milestone 6: Optimization & Polishing)

### 1. 目标
-   提升用户体验，处理所有边缘情况。
-   完善代码质量和可维护性。

### 2. 核心任务
1.  **空状态处理**: 为所有数据表格和列表添加优雅的空状态提示（例如 "暂无云账号，请先添加一个" 并附上一个操作按钮）。
2.  **全局错误处理**: 在 API 客户端中增加更精细的错误处理，例如对 401 (未授权) 错误自动将用户重定向到登录页。
3.  **表单体验优化**:
    -   在提交表单成功后，自动重置表单状态。
    -   对于复杂的表单，考虑在用户离开页面前提示未保存的更改。
4.  **响应式设计**: 确保所有页面在移动设备上都有良好的可用性。
5.  **代码审查与重构**: 审查所有 `TODO` 注释，重构重复代码，完善 hooks 和组件的抽象。
